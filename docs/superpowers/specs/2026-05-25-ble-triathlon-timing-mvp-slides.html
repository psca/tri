Friendly Race Timing MVP

BLE triathlon timing system

A local-first, BLE-assisted timing setup for friendly triathlon and duathlon competitions.

Working hardware + software, not certified chip timing

North Star

Local authority. Cloud spectators.

Laptop is official Scanner, pass detection, route state, manual corrections, and export all run locally.
Cloud is a mirror Cloudflare shows spectator state and stores backup artifacts. It never corrects local truth.

Pass Detector

RSSI policies by state

3

Lap, transition, and finish events can use different detection policies.

  • Open candidate when RSSI/window/packet rules pass for current route event.
  • Estimate pass time using strongest RSSI peak_time.
  • Close only after weak/absent signal clear condition.
  • Transitions can require higher RSSI, longer clear, cooldown, and min_transition_sec.

Transitions

Same gate, different meaning

Route expectation decides whether a pass means lap complete, T1 entry, bike start, T2 entry, run start, or finish.

Boundary events run1_complete_t1_in, t1_out_bike_start, bike_complete_t2_in, t2_out_run2_start.
Auto only if distinct Transition out needs prior transition in, min_transition_sec, clear condition, and new RSSI peak.

Storage

SQLite is canonical

Append-only facts raw_detections, pass_candidates, accepted_route_events, manual_corrections, config_snapshots, sync_outbox.
Disposable projections current_athlete_states, leaderboard_snapshot, receiver_health_current.
Ordering local_sequence_number is primary. Wall clock is display/export data.
Exports JSONL and R2 are derived from committed SQLite ranges.

Manual Adjudication

Corrections are events

No in-place edits to official facts. Manual changes append compensating correction events.

Addinsert_pass, reassign_beacon, manual timestamp.
Changeoverride_time, invalidate_pass, mark corrected.
Statusmark_dns, mark_dnf, mark_dq, lock results.

Cloud Sync

One-way and idempotent

  • Local service sends confirmed events, corrections, snapshots, and freshness.
  • Each outbox item has idempotency_key and payload_hash.
  • Duplicate same key/hash is OK. Same key/different hash is integrity error.
  • D1 is spectator read model. R2 stores exports/bundles. KV is cache only.

Calibration

Trial run decides confidence

10dB

Target useful contrast between gate RSSI peak and transition/rack background.

  • Use actual laptop, dongle, wristbands, gate, and athlete placement.
  • Measure missed reads, duplicate reads, latency, and strongest-RSSI timing.
  • Test walking, running, group passes, wrist orientation, and shared gate transitions.
  • If contrast is poor, use manual-assisted mode for affected events.
